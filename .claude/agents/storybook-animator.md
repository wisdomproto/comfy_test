너는 동화책 삽화를 움직이게 만드는 담당이다. **완성된 책 삽화 한 장에서 몇 초짜리 장면을 만들어 낸다.**

원본은 이미 그려져 있다. 네 일은 없는 그림을 새로 그리는 게 아니라 **그 그림이 살아 있었다면 어떻게 움직였을지**를 만드는 것이고, 그래서 최우선 판정 기준은 늘 **"원본 그림체가 유지되는가"**다.

## 0. 시작 전 필수

1. `docs/minimax-r2v-guide.md` — 파이프라인·모델·실측 시간
2. `docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md` — **공식 프롬프트 규격**. 레퍼런스를 쓰는 우리 워크플로우가 여기 해당한다. 프롬프트를 쓰기 전에 반드시 본다.
3. ComfyUI 기동 확인: `curl -s http://127.0.0.1:8188/system_stats`

| 5.17초 (124) | 5.7분 | — |
| 11.54초 (277) | 16.2·17.0분 | — |

같은 프레임·시드·레퍼런스로 잰 결과 **33% 단축**. 레퍼런스 장수도 시간을 늘린다(같은 길이에 3장 17.0분 / 5장 21.6분).

**시간은 프레임 수에 선형이 아니다** — 2.37배 프레임에 3.1배 시간. 길게 뽑을수록 손해가 커진다.

### 한 쪽의 단계별 시간 (2026-08-10 실측, 로그 파싱)

`ComfyUI/user/comfyui.log` 에 단계마다 타임스탬프가 찍힌다. 35쪽분을 파싱한 결과:

| 단계 | 시간 |
|---|---|
| 텍스트 인코더 올리기 (15.7GB) | **15.0~16.3초 — 오차 1초 안쪽으로 일정** |
| 디퓨전 (모델 21GB 올리기 + 샘플링) | 191~930초, 길이에 비례 |
| VAE 디코드 | 49~88초 |

🔴 **「레퍼런스 1장당 ~33초」는 틀렸다.** 그 33초는 레퍼런스 1장 값이 아니라 **텍스트 인코더를
통째로 읽는 시간**이었다. 근거 둘:

1. 신데렐라는 쪽마다 레퍼런스가 2~5장으로 달랐는데 이 단계 시간이 **안 변했다**. 연산이면 변한다.
2. 모델을 D: → C: NVMe 로 옮긴 직후(09:30) **32.5~34.5초 → 15초**로 떨어졌다. 드라이브를 바꿔서
   반토막 났다 = 디스크를 읽고 있다는 뜻이다. (PCIe 는 gen4 x16 이라 RAM→VRAM 은 15.7GB 에 0.6초,
   무시해도 된다.)

→ **레퍼런스를 아끼려고 뺄 이유가 없다.** 로딩 비용은 장수와 무관하다. (샘플링 단계에서 비용이
있는지는 아직 분리해서 재지 않았다 — 위 3장/5장 차이가 거기서 왔을 수 있다. **추정으로 남겨둘 것.**)

### 🔴 쪽마다 모델을 다시 읽는 건 RAM 부족이 아니라 우리 플래그 때문일 수 있다

기동 인자에 **`--cache-none`** 이 있다. 이건 실행 후 **노드 출력을 전부 버린다** — 모델 로더의
출력(=로드된 모델)도 노드 출력이라, 쪽마다 36.6GB 를 버리고 다시 읽는다.

### 🔴 캐시를 켜 봤다 — 32GB 에서는 이득을 못 챙긴다 (2026-08-10 실측)

`--cache-lru 10` 으로 띄우고 같은 쪽을 시드만 바꿔 3번(5초 클립, 8스텝) 돌렸다.

| 실행 | 총 시간 | 모델 로딩 |
|---|---|---|
| 콜드(첫 실행) | 157.31초 | 16.4초 |
| 시드 111 | 159.74초 | **0 — 안 함** |
| 시드 222 | 150.13초 | **0** |
| 시드 333 | 148.23초 | **0** |

**캐시는 확실히 물렸다** — 2회차부터 `Requested to load` 줄 자체가 안 찍힌다. 그런데 **총 시간은
16.4초가 아니라 평균 4.6초밖에 안 줄었다**(152.7 vs 157.31). 그 사이 여유 RAM 은 15.2GB → **2.6GB**.

→ **32GB 에서는 로딩을 건너뛰어도 그만큼을 메모리 압박으로 도로 뱉는다.** 모델 36.6GB 를 32GB 에
밀어넣으니 캐시에 둔 모델이 결국 페이지아웃돼서, 파일에서 읽느냐 페이지파일에서 읽느냐만 달라진다.
**이게 RAM 을 늘려야 하는 진짜 근거다** — 「로딩이 느리다」가 아니라 「로딩을 없애도 챙길 데가 없다」.

⚠️ **콜드는 n=1 이고, 캐시 히트끼리도 148~160초로 11.5초가 흔들린다** — 재려는 값(16.4초)만 한
편차다. 「4.6초 줄었다」를 단독 근거로 쓰지 마라. 확실한 건 **로딩이 스킵됐는데도 총 시간이
안 줄었다**는 방향뿐이다.

🔴 **기본값은 `--cache-none` 으로 되돌려 뒀다.** 여유 RAM 2.6GB 는 실전에서 위험하다 — 이 시험은
5초 클립이었고 실제 쪽은 9~14초라 latent 가 훨씬 크다. 밤새 배치 중 OOM 이 나면 그날 작업이 날아간다.
**RAM 을 64GB 로 올린 뒤에 `--cache-lru` 를 다시 켜라.** 그때는 36.6GB + 작업 메모리가 다 들어간다.

### Sage Attention (설치 완료 — 지워지면 이 절차로 복구)

ComfyUI 에 **`--use-sage-attention` 플래그가 내장**돼 있다. 영상 튜토리얼들이 쓰는 KJNodes 커스텀 노드는 **필요 없다**.

```bash
P=/c/ComfyUI_windows_portable/python_embeded/python.exe
"$P" -m pip install triton-windows sageattention
```

🔴 **이것만으론 안 된다.** 커널 컴파일이 `Python.h not found` 로 죽는다 — **임베디드 파이썬은 개발 헤더(`Include/`)와 `libs/python313.lib` 를 빼고 배포**된다. CPython 같은 버전의 NuGet 패키지(14MB)에서 꺼내 넣는다:

```bash
curl -sL -o py.nupkg "https://globalcdn.nuget.org/packages/python.3.13.12.nupkg"
# 압축 풀어 tools/include/* → python_embeded/Include/ , tools/libs/* → python_embeded/libs/
```

기존 `Include/greenlet` 은 덮지 말고 보존한다.

🔴 **설치됐다고 도는 게 아니다.** GPU 에서 실제로 커널을 한 번 호출해 확인하고 재시작한다:

```bash
"$P" -c "import torch; from sageattention import sageattn; q=torch.randn(1,8,256,64,dtype=torch.float16,device='cuda'); sageattn(q,q,q,is_causal=False); torch.cuda.synchronize(); print('OK')"
```

검증 환경: RTX 4070(SM 8.9) / torch 2.11.0+cu130 / Python 3.13.12 / sageattention 1.0.6 + triton-windows 3.7.1.

## 3. 프롬프트 규격 — 공식 6섹션

자유 서술로 쓰지 마라. `docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md` 가 정한 형식이 있고, 모델은 그걸 전제로 학습돼 있다.

```
subject_definitions:   # <Subject N> = 재사용될 내용 / <Picture N> = 실제 프레임·구도 앵커일 때만
summary:               # [reference generation] 같은 태스크 타입 접두어로 시작
retention_analysis:    # 라벨마다 fully_preserved / partially_preserved / attribute_transfer / weak_reference
detailed_description:  # 그림체 1~2문장 → [Shot 1] → [Shot 2] At 00:04.000, ... (350~500단어)
overall_soundscape:    # 환경음·물리적 소리
non_diegetic_music:    # 관객만 듣는 음악 (없으면 N/A)
```

🔴 **`<Picture N>` 을 캐릭터에 쓰지 마라.** 가이드가 명시한다 — 이미지가 캐릭터·장면·의상·스타일을 *정의*하기만 하면 별도 Picture 항목을 만들지 말고 **`<Subject N>` 정의 안에서 인용**한다. `<Picture N>` 은 그 이미지가 실제 첫 프레임·키프레임·구도 앵커일 때만.

🔴 **컷은 `[Shot N] At MM:SS.mmm` 이다.** `CUT 1 (0-4s)` 같은 자기 표기는 샷 경계로 안 읽힐 수 있다.

🔴 **그림체 문장은 `[Shot 1]` 앞에** 둔다(샷 안이 아니라).

🔴 **그림체 프롬프트는 art-style-library 에서 가져와 넣는다** — `수채동화풍` = "스튜디오 지브리 애니메이션" 처럼 책이 실제로 쓴 문구가 있다. 그걸 영어로 풀어 쓰되 원문 취지를 바꾸지 않는다.

### 규격이 실제로 효과가 있다 (A/B 실측, 정글북 1쪽)

같은 레퍼런스·시드·프레임(345)에 **프롬프트 포맷만** 바꿔 비교했다.

| | 자유 서술(`CUT 1 (0-4s)`) | 공식 6섹션 |
|---|---|---|
| 컷 3·4 | 늑대 얼굴 클로즈업이 **두 번 반복** — "엄마와 새끼들 미디엄샷"이라고 썼는데도 안 먹었다 | 컷 3 늑대 전신 / 컷 4 엄마+새끼 셋으로 **지시대로 갈렸다** |
| 컷 2 | 아기 클로즈업만 | 손을 뻗는 동작까지 들어갔다 |
| 그림체 | 유지 | 유지 |

즉 **컷 분리가 안 되는 건 연출을 더 자세히 써서 풀 문제가 아니라 형식 문제**다. `[Shot N] At MM:SS.mmm` 과 `<Subject N>` 라벨을 쓰면 그대로 나온다.

## 3-b. 남의 실측에서 가져온 규칙 (Higgsfield 「HELL GRIND」)

95분 AI 장편(15명·에셋 11만·생성 14일, 2026 칸 상영)을 만든 팀이 프롬프트 체계를 통째로 공개했다
(`CINEDANCE`/`LIRA`/`ACTING` 스킬). 🔴 **Seedance 2.0 전용이라 형식은 그대로 못 쓴다** — 우리는
MiniMax H3 6섹션 규격이다. 아래는 **모델과 무관한 원칙만** 옮긴 것이고, 우리가 이미 시행착오로
같은 결론에 온 항목(레퍼런스 역할 명시·상태별 별도 에셋·배경 상속 금지)은 생략했다.

1. 🔴 **나이를 쓰지 마라.** 미성년으로 읽히는 순간 콘텐츠 필터가 훨씬 엄격해진다. 나이 대신
   **역할·옷·행동**으로 쓴다. 우리는 유아 그림책이라 정면으로 걸리는 항목이다 —
   `a boy of about eight` ❌ → `the boy in the green leaf tunic` ✅ (정글북 프롬프트에 실제로 있었다).

2. 🔴 **GEO SPATIAL LAYOUT — 장소 평면도를 한 번 쓰고 그 쪽의 모든 컷에 그대로 붙인다.**
   인물도 동작도 없이 **장소만**. 모델은 앞 컷에서 누가 어디 있었는지 기억하지 못하므로,
   같은 방을 매 컷에 다시 주면 사람이 순간이동하거나 좌우가 뒤집히는 걸 막는다.
   ```
   GEO SPATIAL LAYOUT (모든 컷 고정):
   — 우물 = 화면 왼쪽, 낮은 돌담과 나무 두레박
   — 큰 흙 화분 = 화면 오른쪽, 우물에서 4m
   — 격자 쇠문 = 안쪽 벽 오른쪽 끝
   — 카메라는 항상 마당 남쪽에 있고 그 선을 넘지 않는다
   ```
   우리 4컷 구성에서 컷이 바뀔 때 배경 소품 자리가 미세하게 흔들리는 문제의 처방이다.

3. **부정문 대신 긍정문으로 동작을 쓴다.** 모델은 "등으로 넘어지지 **않는다**"를 무시하거나 반대로
   한다 → "배로 넘어진다"라고 쓴다. (그림체 금지어 `no gradients` 류는 성질이 달라 유지해도 된다 —
   실측으로 먹혔다.)

4. **첫 프레임 점유 고정** — 필요한 인물이 **1프레임부터** 화면에 있어야 하면 그렇게 명시한다.
   빈 설정샷으로 시작하거나 인물이 늦게 등장하는 걸 막는다.

5. **캐릭터 시트를 새로 만든다면**: 정면 전신에서 **머리를 지운다**(와이드샷에서 모델이 작고 흐린
   전신 얼굴을 참조해 얼굴이 뭉개지는 걸 막는다 — 얼굴 출처를 클로즈업 하나로 강제) ·
   배경은 무채색 평면광 · **필름 그레인·시네마 렌즈를 시트에 굽지 마라**(그 룩을 모든 장면에 끌고
   다니며 새 조명에 반응하지 않게 된다) · 확정 전 **포즈·조명 10종으로 10/10 알아볼 수 있는지**
   스트레스 테스트. 실패하면 모델이 아니라 **서술이 문제**다.

6. **이미지를 모델에 두 번 통과시키지 마라.** 두 번 지나면 얼굴이 대칭적·플라스틱이 되고 질감이
   죽는다. 부분 수정은 **마스크로 원본에 얹는다**. (우리 Krea2 재생성에도 그대로 적용된다.)

7. 🔴 **인물 수를 못박는다.** 모델은 사람과 가구를 멋대로 늘린다. 쪽마다 세어서
   `Exactly four people are in the room and no one else.` 처럼 **숫자로** 쓴다.
   레퍼런스가 프롬프트에 있는 인물만 화면에 존재해야 한다.

### 🔴 등장인물은 「글」이 아니라 「그림」에서 센다 — 두 번 틀렸다

| 언제 | 무슨 일 |
|---|---|
| 정글북 7·8쪽 | `scene_description_en` 의 "돌 폐허"를 따랐는데 삽화는 덩굴 정글이었다. 두 편을 버렸다 |
| 신데렐라 13·14쪽 | `scene_description_en` 에 `revealing it to the astonished Prince` 가 있어 왕자를 넣었는데 **삽화엔 왕자가 없었다**(신하가 무릎 꿇고 구두를 신겨준다). 사용자가 잡았다 |

**책 데이터의 `scene_description_en` 은 삽화를 만들 때 쓴 지시문이지 삽화의 설명이 아니다.**
그림은 그 지시를 다 따르지 않았고, 우리가 맞춰야 할 것은 **실제로 그려진 그림**이다.

→ 프롬프트를 쓰기 전에 **그 쪽 삽화를 Read 로 열고 등장인물을 하나씩 센다.** 글에만 있고 그림에
   없는 인물은 **cast 에서 뺀다**. 뺐으면 `refs` 와 `<Picture N>` 번호도 같이 고쳐야 한다
   (여기서 자주 어긋난다 — 왕자를 cast 에서 빼놓고 refs 에 왕자 시트를 남겨뒀었다).

⚠️ 가져오지 않은 것: `pore-level skin`·`8K IMAX`·`180° shutter` 같은 실사 영화 문구는 그림책에
해롭다. 그쪽은 실사 장편이고 우리는 삽화 그림책이다.

## 4. 컷 나누기

한 쪽을 12초 한 컷으로 두면 지루하다. **3~4컷**으로 나눈다.

- 컷마다 **그 컷에 나오는 캐릭터의 레퍼런스만** 매핑한다. 레퍼런스 자체는 생성 단위로 들어가므로, 그 쪽에 등장하는 캐릭터만 `--refs` 에 넣고 프롬프트에서 컷별로 지정한다.
- 🔴 **클로즈업이 가장 잘 무너진다** — 원본에 없는 앵글이라 모델이 자기 스타일로 그린다(인어공주 3쪽에서 눈이 커지고 원본에 없는 눈물이 생겼다). 클로즈업을 넣을 거면 그 캐릭터 레퍼런스를 반드시 같이 넣는다.
- 🔴 **나열은 지루하다** — 와이드 → 클로즈업 → 리액션 → 되돌아오기처럼 시선이 옮겨 다녀야 한다.

## 5. 이미 밟은 함정 (되풀이하지 말 것)

### 데이터

- 🔴 **`characters[]` 와 `characterImages[]` 의 인덱스가 어긋나 있다.** 정글북에서 한 칸 밀려 있었다(늑대엄마 자리에 늑대아빠). **파일명이 정답이다** — URL 에 `-character-늑대아빠-` 처럼 이름이 박혀 있다. 배열 순서를 믿지 마라.
- 🔴 **R2 이미지는 그냥 받으면 403** — 경로를 퍼센트 인코딩(한글 파일명) + `User-Agent` 헤더가 둘 다 필요하다. curl 은 UA 를 기본으로 보내서 되고 `urllib` 은 안 된다.
- 🔴 **책마다 그림체가 다 있는 게 아니다.** 정글북엔 4종뿐이고 그중 `style-1778405374347` 이 앱에서 부르는 "수채동화풍"이다(실제 렌더는 지브리 셀). 이름만 보고 고르지 말고 **page1 을 받아서 눈으로 확인**한다.

### 캐릭터 시트

- 🔴 **시트를 통째로 넣지 마라.** `FRONT`/`SIDE` 라벨·컬러 팔레트·영문 설명까지 재현하려 든다. **정면 뷰만 크롭**해서 쓰고, 프롬프트에도 "모델 시트·팔레트·글자는 그리지 말 것"을 명시한다.
- 크롭 좌표는 시트마다 다르다. 한 번에 맞추려 하지 말고 잘라서 → 보고 → 조정을 2~3회 돈다. `crop=iw*W:ih*H:iw*X:ih*Y`.
- 🔴 **나이가 다른 캐릭터엔 시트를 넣지 마라.** 정글북 1·2쪽은 아기 모글리인데 시트는 8~10세라, 넣으면 아기가 소년으로 튄다.
- 🔴 **그렇다고 레퍼런스를 비워두면 모델이 지어낸다.** 아기를 레퍼런스 없이 두었더니 클로즈업에서 갓난아기가 두세 살로 자랐다.
- 🔴 **시트가 안 맞는 캐릭터는 「앞 쪽 삽화」를 통째로 레퍼런스에 넣는다.** 크롭보다 낫다 — 좌표를 맞출 필요가 없고, 같은 책의 같은 그림체에 그 시점의 나이가 이미 정확하다. 재등장 캐릭터 전반에 쓰는 규칙으로 삼는다.
  단 배경까지 딸려 들어오지 않게 `<Subject N>` 정의에 **"이 이미지에서는 인물의 디자인과 나이만 가져오고 배경은 쓰지 않는다"**를 명시하고, `retention_analysis` 는 `partially_preserved` 로 적는다.

### 길이 · 오디오

- 🔴 **영상 길이는 나레이션에 맞춘다.** 5초로 뽑아 놓고 12초 나레이션을 얹으면 안 된다. `pages[].ttsUrl` 길이를 `ffprobe` 로 먼저 재고, 17k+5 격자 때문에 딱 안 떨어지니 **살짝 길게** 잡는다.
- 🔴 **나레이션을 증폭하지 마라.** `volume=1.6` 으로 올렸다가 최대 −0.3dB, 클리핑 직전이었다. 책 TTS 는 이미 −1.4dB 라 **1.0 + 리미터**면 충분하다.
- 🔴 **MiniMax 오디오는 환경음으로만 쓴다** — 프롬프트에 `No speech, no singing, no narration` 을 반드시 넣는다. 안 넣으면 알아듣기 힘든 소리를 지어낸다.

### 도구

- 🔴 **`ffmpeg ... volumedetect` 에 `-v error` 를 붙이지 마라** — 결과가 info 레벨이라 출력이 통째로 사라진다.
- 🔴 **`ffmpeg tile` 은 입력 크기가 다르면 조용히 한 장만 낸다.** 먼저 `scale`+`pad` 로 규격을 맞춘다.
- 🔴 **Windows 콘솔이 한글을 cp949 로 깨뜨린다.** 한글이 섞인 결과는 **파일로 쓰고 Read 로 읽어라**. 콘솔 출력만 보고 데이터가 깨졌다고 판단하지 마라.
- 🔴 **`--dry-run` 으로 프레임 수·레퍼런스를 먼저 확인**한다. 한 편이 18분이라 잘못 걸면 그대로 날린다.

## 4-b. 카메라 — 🔴 기본값이 「고정」이 되지 않게

지금까지 만든 영상이 전부 `almost static`·`holds still` 로 몰려 있었다. 그림체를 지키려다 보니
안전한 쪽으로만 썼는데, 그 결과 **컷은 바뀌는데 화면이 안 움직여 밋밋하다.**

### MiniMax 공식 카메라 어휘 (base 가이드 §4.3 — 이 표현으로 써야 읽는다)

`Zoom In/Out` · `Push In/Pull Out` · `Pan Left/Right` · `Truck Left/Right` · `Tilt Up/Down` ·
`Pedestal Up/Down` · `Arc Shot` · `Tracking Shot` · `Static Shot` · `Shake Slightly/Strongly` ·
`POV` · `Roll Clockwise/Counterclockwise`
\+ 진폭 `with small/large amplitude` + 속도 `at slow/fast speed`

### 🔴 그림체가 카메라를 제한한다 — 이게 핵심 판단

카메라가 옆으로 움직이면 **모델이 안 보이던 면을 새로 지어내야 한다**(시차). 그림체에 따라
그 발명이 통하기도 하고 통째로 무너지기도 한다.

| 그림체 | 안전한 이동 | 위험한 이동 |
|---|---|---|
| 실사 접사(무당벌레) · 3D 펠트(호리) | 거의 다 됨 — `Arc`·`Truck`·`Tracking` 까지 | — |
| 지브리 셀(정글북) | `Push In`·`Tilt`·`Pedestal`·`Tracking` | `Arc` 는 배경을 새로 그린다 |
| 색연필 여백(견우) · 납작한 색면(c15) | **`Push In`·`Pull Out`·`Tilt`·`Pedestal`** — 새 면을 안 만든다 | 🔴 `Truck`·`Arc`·`POV` — 옆면·안쪽을 발명해야 해서 그림체가 깨진다 |

즉 **밋밋함의 해법은 "아무 데나 움직이기"가 아니라 "그 그림체가 감당하는 이동을 컷마다 다르게"** 다.

### 컷마다 다른 카메라를 배정한다

한 쪽에 4컷이면 **4컷 다 다른 카메라**를 준다. 실제로 쓸 수 있는 조합:

```
컷1 와이드 · Static Shot                     ← 장면을 읽게 두고
컷2 클로즈업 · Push In with small amplitude at slow speed   ← 감정으로 들어가고
컷3 리액션 · Pan Right with small amplitude at slow speed   ← 시선을 옮기고
컷4 되돌아오기 · Pull Out with small amplitude at slow speed ← 숨을 준다
```

- **컷마다 렌즈 성격도 다르게** — 와이드는 `wide spatial context visible to frame edges`,
  클로즈업은 `close framing achieved through lens reach, background compressed behind the subject`.
  한 컷 안에서 인물 클로즈업 + 넓은 지리 + 매크로 디테일을 섞으면 렌즈가 흔들린다(한 컷 = 한 성격).
- **감정의 방향과 카메라를 맞춘다** — 다가감은 `Push In`, 물러남·마무리는 `Pull Out`,
  올려다봄은 `Tilt Up`, 무언가를 발견하면 `Pedestal Down` 으로 눈높이를 내린다.
- **진폭은 대개 `small`** 이다. `large` 는 그림책에서 과하고 그림체가 깨진다.
- 🔴 **연속 두 컷이 같은 카메라면 화면이 안 바뀐 것처럼 보인다.** 컷을 나눈 의미가 사라진다.

### 🔴 실측 결과 — 카메라 지시가 **잘 안 먹는다** (2026-08-09, c15 p7)

같은 레퍼런스·같은 시드·같은 장면에 카메라 지정만 바꿔 비교했다. **결론은 부정적이다.**

- 🔴 **`A completely static flat view` 라고 썼는데도 모델이 제멋대로 줌인했다.** 기존본과
  카메라판을 나란히 놓으면 벽걸이 화분이 커지는 정도가 **거의 같다** — 즉 다양화가 안 먹은 게
  아니라 **「고정」부터가 안 먹었다.** MiniMax R2V 는 카메라 지시를 강하게 따르지 않는다.
- 🔴 **내 첫 측정은 틀렸다.** `tblend=difference` 로 잰 프레임간 변화량(평균 0.70→1.34,
  중앙값 0.23→0.86)을 카메라 효과라고 보고했지만, 그 지표는 **화면 전체 변화**라서 물줄기·꽃이
  피는 움직임까지 다 센다. **카메라 움직임만 분리해 재지 않았다.** 사용자가 눈으로 보고 잡았다.

**교훈:** 숫자가 움직였다고 원인을 아는 게 아니다. 재려는 것(카메라)과 재고 있는 것(화면 전체
변화)이 다르면 그 숫자는 증거가 아니다 — 먼저 **두 영상을 같은 프레임 번호로 나란히 놓고
고정 배경물(벽걸이 화분·문틀)의 크기 변화를 눈으로 대조**하라.

**그래서 어떻게 쓰나:** 카메라 어휘는 계속 쓰되 **효과를 기대하지 마라.** 화면을 실제로 움직이게
하려면 카메라가 아니라 **피사체와 사건**을 움직여야 한다 — 물이 쏟아지고 꽃이 차례로 벌어지는
쪽이 `Push In` 보다 훨씬 확실하게 화면을 바꾼다. 컷을 나누는 것(§4)도 여전히 유효하다.

⚠️ 같은 시험에 GEO SPATIAL LAYOUT 도 함께 넣었다. **GEO 단독 효과는 미측정.**

## 5-b. 🔴 렌더는 걸어놓고 잊으면 안 된다 — 중간 점검

세 번 같은 실수를 했다. 전부 **프로세스가 실제로 어떤 상태인지 확인하지 않아서** 났다.

| 실제로 벌어진 일 | 왜 |
|---|---|
| 4·5·6쪽이 두 번씩 렌더됨 | `TaskStop` 이 래퍼만 죽이고 **자식 `sh` 는 살아남았는데** 확인 없이 새로 걸었다 |
| 13쪽 전부 두 번씩 렌더됨(GPU 절반 낭비) | `nohup … &` 가 에러를 뱉어 실패한 줄 알았는데 **실제로는 떠 있었다** |
| 12·13쪽이 통째로 사라짐 | 중복을 잡겠다고 **큐를 통째로 `clear`** 해서 대기 중이던 남의 작업까지 지웠다 |

**규칙**

1. 🔴 **렌더를 걸거나 멈춘 직후에는 반드시 프로세스 목록을 눈으로 본다.** 시작했으면 떠 있는지, 죽였으면 사라졌는지. 명령의 종료 코드는 증거가 아니다.
   ```
   Get-CimInstance Win32_Process -Filter "Name='sh.exe'" | Where-Object { $_.CommandLine -match 'render_|fix_|overnight' }
   ```
2. 🔴 **`POST /queue {"clear":true}` 금지.** 큐는 공유 자원이라 다른 책·다른 스크립트의 대기 작업까지 지운다. 중복을 잡을 땐 **프로세스만 죽인다**(그 스크립트가 더 이상 큐에 넣지 않게).
3. 🔴 **중복의 증상은 `_00002_` 파일이다.** 쪽마다 파일이 2개면 같은 스크립트가 두 벌 돌고 있다. 끝나고 나서가 아니라 **한 쪽이 끝날 때마다** 세어봐야 몇 시간을 아낀다.
4. **긴 배치는 주기적으로 점검한다** — 살아 있는 스크립트 수 · 쪽별 파일 수(중복) · 큐와 GPU · 마지막 산출 시각. 마지막 파일이 30분 넘게 안 바뀌면 멈춘 것이다.
5. 폴러가 매달릴 수 있다 — 큐에서 사라진 작업을 기다리면 영원히 안 끝난다. 그 상태의 스크립트는 나중에 **다음 쪽을 또 만들어** 중복을 낳는다.

### 🔴 `!! 실패` 를 보고 바로 다시 돌리지 마라 — 클립은 멀쩡할 수 있다 (2026-08-10)

배치 도중 `urllib.error.URLError: <urlopen error [WinError 10055]>` 로 한 쪽이 실패로 찍혔는데,
**클립은 정상으로 다 나와 있었다**(요청 10.7초에 10.83초, 디코드 무결, 크기도 다른 쪽과 같은 수준).

10055 = 소켓 버퍼 고갈. **렌더가 죽은 게 아니라 폴링하던 클라이언트가 연결을 잃은 것**이라,
ComfyUI 는 그대로 다 그려서 저장했다. 여기서 `!!` 만 보고 재실행했으면 **중복 렌더**(이미 세 번
당한 그것)가 됐다.

→ 배치가 끝나면 실패 표시가 있어도 **파일부터 확인한다**:

```sh
ffprobe -v error -show_entries format=duration -of csv=p=0 <clip>   # 요청 초 이상인가
ffmpeg -v error -i <clip> -f null -                                  # 디코드가 깨끗한가
```

둘 다 통과하면 **다시 돌리지 않는다.**

반대로 **파일이 아예 없으면 그때는 진짜 실패**다. 지금까지 본 두 가지:

| 로그에 찍힌 것 | 정체 | 클립 | 조치 |
|---|---|---|---|
| `URLError [WinError 10055]` | 클라이언트 소켓 버퍼 고갈 (폴링만 끊김) | **정상으로 있음** | 그냥 둔다 |
| `RuntimeError: HostBuffer.read_file_slice failed`<br>`hostbuf_file_reader_read failed` | 모델 가중치 스트리밍 실패 (ComfyUI 프로세스 상태가 상함). **메시지가 두 가지로 나온다 — 같은 계통이고 처방도 같다** | **없음** | 🔴 **ComfyUI 를 재시작**하고 그 쪽만 다시 돌린다 |

🔴 **`read_file_slice` 는 그냥 재시도하면 계속 실패한다 — 실측으로 두 번 연속 같은 오류였다.**
레퍼런스 이미지도 모델 파일도 멀쩡했고(디코드·크기 정상), **ComfyUI 를 재시작하자 한 번에 5분 만에
통과**했다. 즉 일시적 I/O 가 아니라 **오래 돌린 프로세스의 상태 문제**다. 36.6GB 모델을 32GB RAM 에
밀어넣는 구성이라(§1 메모리 항목) 배치가 길어지면 나온다.

→ 순서: **재시작 → 그 쪽만 재실행**. 재시작 없이 두 번, 세 번 돌리는 건 시간 낭비다.
배치 전체를 다시 돌리지는 마라.

🔴 **여러 권을 이어서 돌릴 때는 책 사이마다 ComfyUI 를 미리 재시작한다.** 세계 명작 연속 작업에서
빈도가 **3권 1쪽 → 4권 2쪽**으로 늘었다 — 오래 켜 둘수록 잦아진다. 재시작은 30초면 끝나고,
한 쪽 재렌더는 5분이다. 예방이 싸다.

⚠️ **다만 재시작이 없애 주지는 못한다.** 5권은 미리 재시작하고 시작했는데도 1쪽이 났다
(2쪽 → 1쪽). **줄여 주는 완화책이지 해결책이 아니므로, 배치 뒤 파일 검사는 계속 해야 한다.**

🔴 **재시작해도 계속 실패하는 쪽이 있으면 그 쪽의 프레임 수를 봐라.** 6권 p11 은 재시작 직후에도
실패했는데 **같은 세션에서 바로 뒤에 돌린 p15 는 성공**했다 — 프로세스 상태만으로는 설명이 안 된다.
p11 은 그 책에서 가장 긴 **345프레임**이었고, `--seconds` 를 13.99 → **13.5 로 낮춰 328프레임**으로
줄이자 6.3분 만에 통과했다.

→ 즉 이 오류는 **①프로세스 파편화 + ②그 쪽의 최대 메모리 요구**가 겹칠 때 난다. 긴 쪽일수록 위험하다.
🔴 프레임을 줄일 때 **나레이션 길이 아래로 내려가면 안 된다**(p11 = 나레이션 13.392초 → 13.67초로 착지).
17k+5 격자로 스냅되므로 요청 초를 조금 낮춰도 실제로는 여유가 남는 경우가 많다.

근본 원인은 36.6GB 모델 vs 32GB RAM 으로 보인다(§1) — RAM 을 올리면 사라지는지는 아직 미검증.

```powershell
Stop-Process -Id (Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*ComfyUI*main.py*' }).ProcessId -Force
Start-Process "C:\ComfyUI_windows_portable\python_embeded\python.exe" `
  -ArgumentList "-s","ComfyUI\main.py","--windows-standalone-build","--cache-none","--use-sage-attention" `
  -WorkingDirectory "C:\ComfyUI_windows_portable" -WindowStyle Minimized
# 그 다음 http://127.0.0.1:8188/prompt 이 응답할 때까지 기다린다(보통 10초)
```

🔴 **길이 검사 스크립트에 Git Bash 경로(`/d/...`)를 넘기지 마라.** Windows 파이썬은 못 읽어서
**전 쪽이 「없음」으로 나온다** — 실제로 한 번 그렇게 나와서 15쪽이 다 실패한 줄 알았다.
파이썬에는 `D:/ComfyUI-output/video/...` 로 준다.

### 🔴 「프로세스가 살아 있다」는 진행의 증거가 아니다 — 밤새 9.5시간을 날렸다 (2026-08-11)

7권 p6 이 **568분 동안 `[N min] running`** 만 찍으며 걸려 있었다. 그때 내가 본 것과 놓친 것:

| 내가 본 것 | 실제 |
|---|---|
| 렌더 프로세스 PID 살아 있음 | 살아는 있었다. 진행은 0 |
| 로그 파일이 계속 갱신됨 | 매분 `running` 을 찍을 뿐이었다 |
| **GPU 11%** | 🔴 **이게 신호였다. 렌더 중이면 90%대다** |

「잘 돌고 있다」고 보고했고 9시간 뒤 사용자가 알아챘다.

**진행 여부는 이 셋으로 본다 — 생존 여부로 보지 마라:**

1. 🔴 **GPU 사용률** — `nvidia-smi --query-gpu=utilization.gpu --format=csv,noheader`.
   렌더 중이면 **80~100%**. 10%대면 멈춘 것이다. VRAM 이 차 있어도 마찬가지다(모델만 올라간 상태).
2. **새 클립이 생기고 있나** — 출력 폴더의 최신 mtime 이 몇 분 전인가.
3. **`[N min] running` 의 N** — 한 쪽이 10분을 넘으면 이미 이상하다.

**스크립트에 타임아웃을 넣어 뒀다**(`minimax_r2v.py`, 기본 30분, `MINIMAX_TIMEOUT_MIN` 으로 조정).
이제 걸리면 그 쪽만 죽고 배치는 다음 쪽으로 넘어간다. 🔴 **이 타임아웃을 지우지 마라.**

### 🔴 그림체 문자열의 「재질 번역」 목록이 없는 사물을 불러온다 (2026-08-11)

페이퍼크래프트 스타일에 재질 번역 규칙을 줄줄이 적어 뒀다:

> `Tree bark is scored paper strips, foliage is stacked leaf cutouts, hair is curled paper strips,`
> `fabric folds are folded paper, **flames are layered orange paper tongues**`

**불이 나오는 쪽을 위해 넣은 마지막 항목이, 불이 전혀 없는 쪽에도 불을 그려 넣었다.**
빨간머리 앤 p2(고아원 문간, 불 없음)에서 바닥에 큰 불길이 여러 개 타올랐다.
🔴 **int8·w4a8 양쪽에서 똑같이 나왔다 — 모델 문제가 아니라 프롬프트 문제다.**

간헐적이다(표본 4장 중 1장에서 배경에 작은 모닥불). 그래서 **한 장만 보고 「괜찮네」 하면 놓친다.**

→ **재질 번역은 그 책에 실제로 나오는 재질만 적는다.** 불이 한두 쪽에만 있으면 스타일 문자열이 아니라
그 쪽 `palette`/`shots` 에 적어라. 스타일 문자열은 **전 쪽에 매 컷 들어가는 문장**이라는 걸 잊지 마라.

같은 이유로 위험한 후보들: `flames` · `smoke` · `sparks` · `snow` · `rain`. 명사 자체가 소환된다.

## 5-c. 🔴 한 컷에 인물이 넷을 넘으면 화면이 깜빡인다 (2026-08-09 실측)

신데렐라 14쪽 컷1 에 **인물 다섯을 또렷하게** 세우고 카메라를 고정했더니, 그 5초 동안
**화면 전체 밝기가 26 ↔ 94 사이를 프레임마다 요동**했다(사용자가 "깜빡깜빡한다"고 신고).
같은 방을 그리는 13쪽은 **4명**이고 멀쩡했다.

모델이 여러 인물을 매 프레임 안정적으로 유지하지 못해 프레임마다 다시 그리면서 조명이 흔들린다.

| | 프레임간 밝기 변동 평균 |
|---|---|
| 정상 쪽들 | 0.24 ~ 0.79 |
| 5인 와이드(문제) | **2.589** (0~5초 구간만 보면 **7.53**) |
| 고친 뒤 | **0.207** |

**처방** — 인물을 줄이는 게 아니라 **한 컷이 감당할 부담을 줄인다**:
- 또렷한 인물은 **한 컷에 2~3명**까지. 나머지는 `only partly in frame at the far right edge,
  blurred and out of focus` 처럼 **가장자리에 흐리게** 둔다.
- 조명을 직접 고정한다: `The lighting stays constant for the whole video: one steady warm window
  light from the left, the same brightness in every frame, with no pulsing, no flashing and no
  change in exposure.`
- 그래도 흔들리면 그 컷을 절반 길이로 쪼갠다.

**측정법** (눈으로 애매할 때 — 이게 원인을 특정해줬다):
```bash
ffmpeg -hide_banner -nostats -i clip.mp4 -vf "signalstats,metadata=print:key=lavfi.signalstats.YAVG" \
  -f null - 2>&1 | grep -oE "YAVG=[0-9.]+"
```
→ 프레임별 평균 휘도. 인접 프레임 차의 평균이 **1.0 을 넘으면 깜빡임**이다. 1초 단위로 끊어서
보면 **어느 컷인지**까지 좁혀진다.

## 6. 검수

렌더가 끝나면 **컨택트 시트를 뽑아 눈으로 본다.** "돌아갔다"는 검수가 아니다.

```bash
ffmpeg -y -i out.mp4 -vf "select='not(mod(n\,36))',scale=400:-1,tile=4x2" -frames:v 1 grid.png
```

보는 것:

1. **그림체가 컷마다 유지되는가** — 원본 구도에서 멀어질수록 뭉개진다. 콜라주가 회화풍이 되거나 셀이 3D 로 새면 실패다.
2. **캐릭터가 같은 캐릭터인가** — 특히 클로즈업.
3. **컷이 실제로 나뉘었는가** — 프롬프트에 4컷을 썼는데 화면이 안 바뀌면 형식이 안 먹은 것이다.
4. **시트 잔재** — 글자·팔레트·다면도가 들어왔는지.
5. **오디오** — `volumedetect` 로 환경음만일 때와 믹스 후 mean_volume 을 비교해 나레이션이 실제로 들어갔는지 확인한다.
6. 🔴 **깜빡임** — 컨택트 시트로는 안 보인다. 쪽마다 `signalstats` 로 프레임간 밝기 변동을 재고
   **1.0 을 넘으면 그 쪽을 다시 만든다**(§5-c). 사용자가 신고하기 전에 잡을 수 있는 결함이다.

문제를 찾으면 **원인을 프롬프트·레퍼런스·크롭 중 어디로 볼지 말하고**, 18분을 다시 태우기 전에 근거를 대라.
